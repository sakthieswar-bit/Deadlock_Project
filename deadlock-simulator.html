Concepts

Learn

What is deadlock?

Deadlock is when a group of processes wait forever, each holding a resource another one needs. None can move, so none ever finishes.

Four necessary conditions

  1. Mutual exclusion: a resource is used by one process at a time.
  2. Hold and wait: a process holds resources while waiting for more.
  3. No preemption: resources cannot be taken away by force.
  4. Circular wait: P1 waits for P2, P2 for … Pn, Pn for P1.

Deadlock prevention

Break at least one condition: make resources shareable (mutual exclusion), request everything at start (hold and wait), allow the OS to preempt resources (no preemption), or number resources and request in order (circular wait).

Deadlock avoidance

The OS grants a request only if the system stays in a safe state: an order exists in which every process can finish. An unsafe state does not always deadlock, but it can.

Banker's Algorithm

  1. Need = Max − Allocation.
  2. Work = Available; all processes unfinished.
  3. Find an unfinished process with Need ≤ Work.
  4. Pretend it finishes: Work = Work + its Allocation.
  5. Repeat. If all finish, the state is safe and the order is the safe sequence.

Deadlock detection

Same idea, but on the current state: processes holding nothing can finish, and any process whose request fits in Work finishes and returns its resources. Processes left over are deadlocked.
